## 3. 工作台 Codex 需要实现的改动

1. 找到现有卡片配置，把其“打开”链接改为工作台内部的服务端签发路由，例如 /integrations/teaching-risk/open。该路径是建议新增的工作台路径，不是声称已经存在。
2. 签发路由必须读取工作台自己的已验证登录会话，取真实员工工号、启用状态。不能相信URL参数、浏览器传来的job_number、姓名或role。
3. 未登录时跳转工作台登录，登录后返回固定签发路由；next/return参数不能形成任意跳转。员工未启用则拒绝。
4. 由工作台后端用独立 WORKBENCH_SECRET 签JWT，签发后302到看板的固定HTTPS回调。密钥不能进入浏览器JS、仓库、日志或回复。
5. 配置看板 WORKBENCH_LOGIN_URL 为这个签发路由的最终HTTPS完整地址。看板直接访问时显示“通过工作台登录”和“密码登录”两种入口；工作台打开时自动交换身份，无需再次输入看板密码。
6. WORKBENCH_LOGOUT_URL 指向工作台真正退出会话的固定HTTPS路由，与签发入口同源。看板工作台会话退出后清除本地会话并跳转该路由；独立密码退出只清除看板会话。
7. 工作台停用员工时，服务端调用看板 /api/auth/workbench-status（第5节），停用同一工号，清除两类登录会话。推送失败应保留持久重试任务、有限重试并告警；不要宣布已完成全系统停用。恢复账号必须由看板管理员重新批准，不通过此接口自动开权限。
8. 工作台全局admin、display_name等只供展示，不决定看板角色。无需在工作台保存看板独立密码。

## 4. JWT契约（两端严格一致）

算法HS256，header为 {"alg":"HS256","typ":"JWT"}。签名使用专门生成、至少32字符的随机密钥；不能复用工作台SECRET_KEY或EEO_SYNC_TOKEN。

```json
{
  "iss": "sales-workbench",
  "aud": "ai-risk-dashboard",
  "iat": 1790000000,
  "exp": 1790001200,
  "jti": "unique_random_id_at_least_16_characters",
  "job_number": "EEO04410",
  "enabled": 1
}
```

以上时间是说明用占位数，实际必须使用当前UTC Unix秒。iat/exp为整数，exp>iat，最长1800秒；建议1200秒。jti每次签发随机且唯一（16–128位字母、数字、下划线或横线），一次票据只能成功交换一次。缺少jti的旧对接须升级；不要重复使用同一JWT打开新标签页。

- 看板校验签名、iss、aud、工号格式、enabled、过期、最长30分钟和票据重放。
- 有效工号还必须在看板显式授权表中启用。即使JWT带role=admin，仍不能改变权限。
- EEO04410须映射到admin；任何其他工号映射为admin将被拒绝。不能从显示名称自动猜测身份或客户归属。
- 成功建立独立的HttpOnly、Secure、SameSite=Lax Cookie，最长30分钟、不滑动续期；响应无缓存及no-referrer。GET回调成功后马上302到 /，不会把JWT交给React state或页面DOM。
- /api/auth/workbench失败也302到无票据首页（login_error=sso_denied），不会无限跳转工作台。
- 回调参数使用URL编码。工作台跳转目标必须是服务器固定配置，禁止让访客指定回调。
- nginx/代理不要记录含sso_token的查询串。可为看板设置专用日志格式只记录$request_method、$uri、$status，不记录$request或$request_uri；不要更改其他站点日志配置。
- 此版本根路径部署；不要未经测试直接挂到 /risk/ 子路径，首页、API和静态资源均按根路径生成。

## 5. 工作台停用接口

工作台后端通过HTTPS调用：

```http
POST <看板HTTPS origin>/api/auth/workbench-status
Authorization: Bearer <WORKBENCH_ACCOUNT_TOKEN>
Content-Type: application/json

{"jobNumber":"EEO90001","enabled":0}
```

EEO90001仅为格式示例，不是实际授权。WORKBENCH_ACCOUNT_TOKEN是双方后端专用、单独生成的32–200字符随机机器令牌；不与JWT密钥、EEO同步密钥共用。不要把它放在卡片链接或浏览器请求里。

成功200 {"ok":true}，立即停用该既有工号/内部账号并删除密码、工作台两类会话。不接受enabled=1，不接受角色或客户范围，不创建用户。无令牌401、未配置503、无映射404。重复停用不会重新启用账号。此接口只能收窄权限。

工作台会话在上游退出/票据到期后最迟30分钟失效；账号停用还需可靠调用本接口，以防独立密码仍然登录。重新启用由看板管理员使用显式批准的工号映射，enabled:1；变更会清理旧会话。

## 6. 看板生产配置

在服务器受限环境文件中设置；真实值不可发到对话、仓库或文档。使用 dashboard/deploy/env.template：

```text
AUTH_MODE=hybrid
DASHBOARD_ORIGIN=<看板最终HTTPS origin，不含路径或结尾斜杠>
WORKBENCH_SECRET=<独立随机JWT签名密钥>
WORKBENCH_ACCOUNT_TOKEN=<独立账号停用机器令牌>
WORKBENCH_LOGIN_URL=<工作台HTTPS签发路由>
WORKBENCH_LOGOUT_URL=<工作台HTTPS退出路由>
WORKBENCH_REVOKE_MODE=ttl
EEO_SYNC_TOKEN=<原有独立数据同步密钥，保持原值>
```

DATA_DIR和PORT由现有服务单元提供，保留原数据库绝对路径和端口，不随发布覆盖。仅SSO时可用AUTH_MODE=workbench，但这不满足用户要求的双入口；正式此次部署采用hybrid。工作台登录/退出URL必须固定且同源HTTPS，不带查询参数或账号信息。没有完整配置时新生产启动会失败并明确报错，不能退回local模式。

## 7. 工号映射与独立密码

账号配置命令在dashboard目录，使用已授权映射文件（文件不提交GitHub）：

```bash
DATA_DIR=/var/lib/teaching-risk node scripts/provision-workbench-users.mjs /secure/approved-mapping.json
```

新管理员映射格式：

```json
[{"jobNumber":"EEO04410","username":"EEO04410","role":"admin","consultantName":null}]
```

若原库已有用户管理员，不要重复新建导致冲突。先只查询用户id/账号/角色/工号（不查询密码字段），确认该管理员确为用户本人，再在已批准映射中加userId关联；不得把不明访客创建的管理员直接认领。发现未知管理员须核查审计，按确认结果停用并撤销会话，不删除业务数据。

其他员工映射必须role=consultant、明确consultantName及工号；客户快照中的consultantJobNumber须与之相符。没有归属的已授权销售可以登录但只看到空范围。姓名仅展示，不授予数据权限。不要将所有工作台员工自动导入并开通。

首次密码设置可由EEO04410工作台登录后，在“系统设置”中为自己或已授权销售设置12–128位独立密码。紧急恢复使用服务器交互终端：

```bash
DATA_DIR=/var/lib/teaching-risk node scripts/set-account-password.mjs EEO04410
```

交互隐藏输入并确认；拒绝命令行传密码、重定向文件或非交互管道。只保存PBKDF2哈希和随机盐，不打印/保存明文，不提供密码查看。设置密码会撤销该账号原有密码会话。密码登录最多每账号每10分钟5次尝试；限流有1000条内存上限。

本次开发未修改任何现有业务账号密码。两种登录互相切换时清除另一种Cookie，避免误用残留身份。用户/映射停用均拒绝访问。

3. 保留1.0完整release和原库备份。安装本包到新的独立release目录，不覆盖当前有效release；业务库保持外置，不拷贝Windows依赖。执行npm ci、npm run typecheck、npm run lint、npm run build；预构建ZIP也可用npm ci --omit=dev安装运行依赖。
4. 与工作台Codex按第3–6节配置HTTPS和专用密钥；用批准映射建立EEO04410/销售授权，检查已有管理员归属。不要调用公开注册接口。密码由用户或维护方安全设置，不通过聊天交换。
5. 停止明确属于看板的旧服务后，以原DATA_DIR启动新服务。启动自动增加workbench_ticket表和索引，不删除/清空原客户、EEO、CRM、日志或账号。首次切换会要求旧登录会话重新验证；旧会话不作为兼容性依据。

## 9. 共同验收（全部通过才称为接通）

| 场景 | 预期 |
|---|---|
| 空库匿名注册 | /api/auth/bootstrap=410，数据库没有新增管理员；页面无注册入口 |
| EEO04410从工作台卡片进入 | 无需再次输入看板密码，管理员权限、可见全局客户 |
